# Noduma status

Outside uptime check for the [Noduma](https://github.com/danielitogomez/Noduma) coordinator, built on [Upptime](https://github.com/upptime/upptime). It runs on GitHub Actions, not in the Civo cluster, so it still reports when the whole cluster is down (Noduma SPEC-047).

- **What:** `GET /healthz` on `app.noduma.dev` (coordinator), `noduma.dev` and `www.noduma.dev` (homepage) and `onboarding.noduma.dev` (contributor portal, with its database) every 5 minutes; down unless it answers 200; degraded above 5 s. A failed check is tried 3 times in all (2 retries), 10 s to connect and 15 s per try, no curl-level retries: a dead site is reported in under a minute. GitHub delays scheduled runs by hours, so `uptime-loop.yml` starts Uptime CI itself every 5 minutes and restarts itself every 5 h 45 min; its hourly cron only revives a broken chain (Noduma SPEC-047 D6). To stop the checks, disable "Uptime loop" in the Actions tab.
- **Alerts:** one Telegram message per change of state to the operators' group "NodumaOps", sent by `.github/scripts/alert.sh` after each check (secrets `NOTIFICATION_TELEGRAM_BOT_KEY`, `NOTIFICATION_TELEGRAM_CHAT_ID`): the sites that went down grouped in one message ("all sites down" when every site is, with the open Civo incident from status.civo.com if there is one), then one "back up" message. Nothing more while a site stays down; slow (degraded) shows on the status page only. Upptime itself sends nothing; it still opens and closes an issue per site outage. Jail test: `bash .github/scripts/test_alert.sh`.
- **Status page:** https://status.noduma.dev
- **Configuration:** `.upptimerc.yml`. The workflows use the default `GITHUB_TOKEN` (no personal token, no GitHub App), each with only the permissions it needs (repository default: read); every action is pinned by commit SHA, checked by Noduma's `scripts/check_workflow_pins.py`; no secret reaches the Upptime action (the two Telegram ones go to `alert.sh` only). Upptime's `setup` and template-update workflows were removed: they rewrite the workflow files, which needs a token with the workflows scope, and the update ones track `@master`. To change a schedule or upgrade Upptime, edit `.github/workflows/` by hand.
